05 / test automation strategy
Choose the engine for the product.
Framework / interfaceFeasible whenReview / tradeoff


pytest + CAN librariesPython teams; custom signal and log analysisFlexible, transparent and CI-friendly. Team owns adapters and evidence validation.


Robot FrameworkReadable acceptance scenarios for mixed teamsKeyword reuse and clear reports. Complex temporal logic belongs in libraries.


CANoe + vTESTstudioVector-based network and diagnostic ECU testsStrong bus simulation integration. Account for licensing and Windows agents.


AutomationDeskdSPACE/XIL HIL and plant/fault workflowsBench ecosystem and cross-level reuse. Requires real-time model and package setup.


ecu.testHeterogeneous automotive tools and benchesCoordinated tool execution and Jenkins integration. Verify adapter support.


Simulink Test + CoverageModel-based control softwareHarnesses, requirement links and coverage. Model and target must be correlated.


ASAM XILCompatible benches requiring portable interfacesInterface abstraction standard; select an execution engine alongside it.


Why Jenkins in testing?
Automatic regression after trusted commits, distributed bench agents, exclusive bench locks, managed credentials, JUnit trends and archived evidence.
Time-critical execution belongs in the HIL engine. Jenkins orchestrates jobs and gates releases; it does not provide deterministic real-time stimulation.
How to roll it out
Review requirements and oracles → pilot known-good/bad captures → integrate one bench → prove repeatability → connect Jira → automate full regression → expand coverage.
Assess safety work products, tool confidence and independent review under the project's applicable ISO 26262 plan.
